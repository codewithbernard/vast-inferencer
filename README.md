# Vast Inferencer

Stateless FastAPI service that accepts a ComfyUI WAN 2.2 workflow, returns a generated request ID immediately, and uses [Upstash QStash](https://upstash.com/docs/qstash) to call a [Vast Serverless](https://docs.vast.ai/guides/serverless) `/generate/sync` endpoint in the background.

The public response status is `in_progress`. That is this API's acknowledgement, not a status reported by Vast. [`/generate/sync`](https://docs.vast.ai/guides/serverless/comfyui-wan-2.2) returns only after generation finishes, so the QStash delivery is what waits on Vast. This service does not store job status. The project webhook is the completion channel, and the configured S3 bucket receives the rendered file.

## Flow

1. `POST /v1/generations` checks the bearer token and project ID, generates a request ID, and publishes that ID, project ID, and workflow to QStash.
2. The API responds `202` with `status: "in_progress"`.
3. QStash signs and delivers the job to `POST /internal/generations`.
4. That route loads the project from `src/vast_inferencer/registry.py`, reads its S3 secrets from the environment, and calls that project's Vast `/generate/sync` endpoint.
5. Vast uploads the video to the project bucket and sends the terminal result to the project webhook.

S3 credentials, the Vast API key, the QStash token, and webhook secrets are never accepted from callers and are not included in the QStash message.

## Local setup

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
uvicorn app:app --app-dir src --reload
```

Open [http://127.0.0.1:8000/](http://127.0.0.1:8000/) for the request playground. Paste your bearer key in the form (the same value as `API_BEARER_KEY`); it is kept in page memory only and is sent only with `POST /v1/generations`.

## Configuration

Set these in `.env` locally and as encrypted environment variables on Vercel:

| Variable | Purpose |
| --- | --- |
| `VAST_API_KEY` | Vast API key used by the Python SDK |
| `QSTASH_URL` | QStash region URL, such as `https://qstash-us-east-1.upstash.io` |
| `QSTASH_TOKEN` | Token used to publish background jobs |
| `QSTASH_CURRENT_SIGNING_KEY` | Current QStash signing key |
| `QSTASH_NEXT_SIGNING_KEY` | Next QStash signing key, used during key rotation |
| `PUBLIC_APP_URL` | Exact public origin QStash calls, without a trailing slash |
| `API_BEARER_KEY` | Bearer token required by `POST /v1/generations` |

Projects and Vast endpoint names are declared in [`src/vast_inferencer/registry.py`](src/vast_inferencer/registry.py). `ai-ofm-studio` uses the BunnyCDN storage zone of the same name. Its storage password is `AI_OFM_STUDIO_STORAGE_PASSWORD`. Add another project in that file when you add another endpoint.

Timeouts, retries, and QStash delivery limits are constants in [`src/vast_inferencer/limits.py`](src/vast_inferencer/limits.py). They are not environment variables.

A caller can add `webhook_extra_params`. Those values override the project extras except `request_id`, which is always the ID generated by this API.

## API

```bash
curl -X POST http://127.0.0.1:8000/v1/generations \
  -H "Authorization: Bearer $API_BEARER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "ai-ofm-studio",
    "workflow_json": {"90": {"class_type": "CLIPLoader", "inputs": {"clip_name": "umt5"}}},
    "webhook_extra_params": {"user_id": "12345"}
  }'
```

```json
{
  "request_id": "5d0c0c3e-1f2a-4d4e-9c1a-0a0c2f5e6b7d",
  "status": "in_progress"
}
```

`workflow_json` must be ComfyUI API-format JSON. The string `__RANDOM_INT__` is replaced by the Vast worker before the workflow runs. `GET /health` is unauthenticated.

The project webhook receives Vast's terminal payload. For the current ComfyUI wrapper that includes `id`, `status`, `message`, `output`, `timings`, and `extra`. Presigned S3 URLs in `output` expire; keep the bucket and object key if the file must remain available. See the [WAN 2.2 template](https://docs.vast.ai/guides/serverless/comfyui-wan-2.2) for the full response shape.

## Deployment

Vercel loads the FastAPI app from `src/app.py` through `[tool.vercel] entrypoint = "src.app:app"` in `pyproject.toml`. The function `maxDuration` is 800 seconds, which requires a Vercel plan that allows it.

After deployment, confirm `PUBLIC_APP_URL` is the canonical HTTPS origin. QStash signature checks compare the signed URL with `${PUBLIC_APP_URL}/internal/generations`.

QStash must be allowed to wait at least as long as the function duration. The delivery limit is `QSTASH_TIMEOUT` in `src/vast_inferencer/limits.py`.

## Limits

- Cold worker startup, video generation, and S3 upload must finish before both the Vast worker timeout and the Vercel function limit. This service uses the stock synchronous route and accepts that risk.
- QStash delivery is at least once. The request ID is the deduplication ID for ten minutes, which prevents a duplicate publish of the same ID. It does not make Vast execution exactly once. A timeout after Vast has started can cause another delivery to generate again.
- There is no status or result endpoint. If the background call fails before Vast accepts it, the project webhook is not called. Permanent QStash failures return HTTP 489 with `Upstash-NonRetryable-Error: true`; transport failures return HTTP 502 so QStash can retry.
- Do not put storage credentials in the workflow JSON. Publishing is rejected if a configured secret appears in the QStash message.
